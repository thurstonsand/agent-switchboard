# Agent Switchboard

## Destination

An accepted design doc, refined TUI mocks, and an execution plan that a single autonomous implementation agent can carry out in one run (`/grill-me` Gates 2 and 3), for Agent Switchboard (`swb`): a TUI and CLI that tracks every managed Pi session on this machine from its first turn until I archive it, across reboots. Its **Deck** shows the roster beside a live, interactive **Stage** of the selected session. That works in any terminal, because everything runs on two dedicated tmux servers. (Redirected from the Ghostty-tab Dispatcher on 2026-10-06; see [the launch contract](tickets/08-launch-hosting-reopen-contract.md).)

- Standing decisions (charted 2026-10-05; redirected by [the launch contract](tickets/08-launch-hosting-reopen-contract.md) on 2026-10-06, which holds the detail):
  - **Substrate**: two tmux servers.
    - Sessions server (`tmux -L swb`): hosts each managed session headless, from a config `swb` embeds. tmux is an execution engine: nothing from the user's tmux config reaches it, and it has no prefix.
    - UI server: owned by `swb`; holds each **Deck**.
    - There's no daemon. The tmux servers plus the db are the persistent truth, and every Deck renders from them.
  - **Deck**: `swb` opens a Deck with a roster pane and a **Stage** pane. The Stage is a real tmux client of the sessions server, and moving the cursor switches which session it shows. It's interactive, and it has its own scrollback. Each `swb` invocation gets its own Deck. It behaves the same in any terminal, inside or outside tmux. Ghostty and GhosttyKit are not dependencies.
  - **Wake**: lazy by default. `w` wakes a dormant session in the background and never takes the keyboard. Enter wakes it and takes the keyboard onto the loading card; `esc` backs out to the roster while the wake continues. `hover = "eager"` starts pi after 500 ms on a row instead. The TUI never waits on pi: it shows a loading marker, and navigating away is instant. Idle live pis nobody is viewing are reaped after `reap_after` (30 min). A snappy TUI is paramount.
  - **Dormant card**: the whole conversation from the transcript, cropped from the top.
  - **Editor**: one per directory, shared by every session in it. The Stage shows one of three **views**: pi, the editor (`M-a e` swaps), or a 65/35 editor-and-pi split (`M-a v`). Each session remembers its view.
  - **Keys**: the Deck prefix is `M-a` (rebindable). The roster uses bare keys.
  - **Managed**: a pi that `swb` started (a consumed `SWB_MANAGED` token). Bare `pi` is unsupported.
  - **Archive**: from the TUI (`a` toggles both ways), `swb archive <id>`, or `/archive` in pi. All three refuse while a turn is running ("turn running: wait for it to complete"). Archiving an idle live session kills it immediately, and unarchiving only clears the mark. Quitting never archives, and any new turn unarchives. Archived sessions are listed flat and can be unarchived.
  - **Reboot**: lazy. The roster comes back as it was, and a process starts only on `w`, Enter, or eager hover. There is no revive. A process that died mid-turn shows as ⚠ **interrupted**; a dormant idle session shows as idle. No turn is ever auto-continued.
  - **State axes**: runtime (live/dormant, mostly internal), activity (working/blocked/idle), unseen, and open/archived. A **Visit** is 1 s on the Stage of a focused Deck. Users see session titles, or the session id when there is no title, never tmux names.
  - **Roster**: open sessions grouped by **Project** (git repo plus its worktrees). Projects sort alphabetically and stay put; sessions within a project sort newest activity first, and the cursor tracks the selected session id. Then **Inactive** (72h with no activity; never applies to blocked or unseen sessions), grouped by project. Then **Archived**, an inline collapsed section, flat. Headers toggle by click, Enter, or space.
  - **Copy**: `y` copies the command that opens the session; `Y` copies `@session:<uuid>`.
  - **Store**: one SQLite db, written by both the Pi recorder (runtime-native: `bun:sqlite` in the compiled Pi on the work Mac, `node:sqlite` under Node) and `swb`, at `${XDG_STATE_HOME:-~/.local/state}/agent-switchboard/swb.db`. Start empty; nothing migrates from the recovery tree.
  - **Scope**: Pi only, this host only. pi-sessions subagents are excluded.

## Decisions so far

<!-- one line per closed ticket -->

- [T3 Code thread-state model, the parts to adapt](tickets/03-t3-thread-state-model.md): copy T3's orthogonal axes and rules, not its event log. Use one session row plus a current-runtime row, and derive Open/Archived, Live/Dormant, Unseen, and Interrupted rather than storing a composite status. Visit is a monotonic watermark. T3 calls restart-killed runs `cancelled`, so our Interrupted is a deliberate local choice.
- [Ghostty scripting surface for tab create and focus](tickets/04-ghostty-tab-control.md): Ghostty 1.3.0+ (this Mac has 1.3.1) can create a one-terminal tab with cwd and command in one step, and can focus an exact terminal while bringing its window forward. Proposed commands: `gty new-tab --cwd … --command … [--tty …] [--wait]` (prints the new tty) and `gty focus-terminal --tty … [--wait]`.
- [Recording video evidence on the work Mac](tickets/05-evidence-recording.md): versioned VHS tapes for TUI scenarios, rendered to MP4. Real Ghostty flows are captured with built-in `screencapture -v -R`, driven by `gty input` / `tmux send-keys`, once Screen Recording access is approved. Reboots are demonstrated as clearly labeled process loss; boot ids are never faked. Videos are attached to the PR, not committed.
- [Pi lifecycle signals for session state](tickets/01-pi-lifecycle-signals.md): working begins at `agent_start`; blocked is any unresolved `glimpseui:attention` id; only `agent_settled` means idle. The in-turn flag is written synchronously, so a dead process with it set is interrupted, and with it clear is dormant. A user `message_start` unarchives. Managed means the process is on the `tmux -L sessions` socket. Subagents are recognized by pi-sessions' durable child bootstrap. Excerpts are cached from `message_end`. Watch: a launch reports `startup` even for existing history, `ctx.hasUI` is true under RPC, Pi swallows extension errors, and no event fires after the JSONL write, which leaves a narrow power-loss race between db and transcript.
- [Cross-language SQLite on the work Mac](tickets/02-cross-language-sqlite.md): one WAL db is safe across runtime-native SQLite and modernc, given a 5 s busy timeout, `BEGIN IMMEDIATE` writes, and `synchronous=FULL`. Bidirectional writes and recovery after SIGKILL were verified. The TUI polls `PRAGMA data_version` every 250 ms on one connection (about 4 µs per poll, ~100 ms detection). The db lives at `${XDG_STATE_HOME:-~/.local/state}/sessions/sessions.db` (dir 0700, file 0600). Pi on the work Mac is a Bun executable, so `node:sqlite` doesn't resolve; use pi-sessions' adapter. pod042 is unverified.
- [Shared session db: schema and ownership](tickets/07-shared-db-schema-and-ownership.md): three tables. The recorder writes `sessions` and `runtimes`; `marks` (archived, visited) holds user intent and is also written by pi's `/archive`. States are derived, not stored: Interrupted is "not live and phase isn't idle", and unarchive is "a newer prompt beats `archived_at`". The CLI owns migrations and the recorder asserts `user_version`. A failed recorder shows a red footer status. Visits are written on focus-in and focus-out, and a focused session is never unseen. `ignore` is deleted, and testing is e2e only.
- [Driving a real pi deterministically for e2e tests](tickets/13-deterministic-pi-e2e.md): pi-ai's faux provider, registered by one scenario extension, scripts replies, real tool calls, held turns, and attention spans offline at zero token cost. Real interactive pi runs inside a private tmux socket, is driven with `send-keys`, and is asserted through sentinels plus the real db/CLI; a proof ran on Pi 0.99.2. Reuse pi-sessions' disposable state and cleanup. The same harness drives VHS; Ghostty focus needs real screen capture. Watch: faux isn't in Pi's built-in registry, and a disposable HOME breaks the mise `pi` shim, so pin the real executable first.
- [TS TUI and single-binary options on the work Mac](tickets/12-ts-tui-and-binary-options.md): TypeScript is viable using standalone `@earendil-works/pi-tui` and an arm64 `bun build --compile` executable. Compiled `bun:sqlite` works. Startup is 14.8 ms median against Go's 12.2 ms, but the binary is ~62 MB against 5 MB. OpenTUI is pre-1.0 and not on Artifactory. Ink is mirrored but has no mouse support. Catch: on 2026-10-05 the mirror only carried pi-tui up to 0.87.1. By 2026-10-06 it resolved 1.0.0, so the lag is real but brief.
- [Repo and language for sessions v2](tickets/11-repo-and-language.md): **Agent Switchboard**, at `thurstonsand/agent-switchboard` with CLI `swb`. TypeScript on Bun, with pi-tui (tracking latest) and a compiled arm64 binary. Bun workspaces on `main` (`packages/cli`, `packages/pi`, `packages/shared`). One tag-driven release builds the binary and regenerates a `pi` branch that holds only the bundled extension. ansiblonomicon installs `swb` via mise `latest` and the extension via `git:…@pi`. Its GhosttyKit viewer seam was superseded by the Deck (ticket 08). The Deck later superseded that seam.
- [GhosttyKit tab and focus commands](tickets/06-ghosttykit-tab-and-focus-commands.md): dropped. The Deck needs no Ghostty integration.
- [Roster TUI prototype](tickets/09-roster-tui-prototype.md): three mock rounds. Stage is internal-only. Lazy wake, with Enter taking the keyboard and `esc` backing out. Inline Archived, `a` toggles, `h`/`l` focus and headers. The dormant card shows the whole conversation. Three remembered views, including the 65/35 split. Reaping after 30 min. Copy and theme work through both layers with an embedded sessions-server config.
- [Retiring the recovery tree](tickets/10-retiring-the-recovery-tree.md): retire now, before `swb` ships. Delete every recovery piece and its data on all hosts. pod042 loses tracking. `ide` stays, minus its dead tmux-name parsing. Design 15 is superseded. Installing `swb` is the plan's last unit, with npm for personal pi hosts (amending ticket 11). E2E tests must include real subagents and handoffs.
- [Launch, hosting, and reopen contract](tickets/08-launch-hosting-reopen-contract.md): the Dispatcher became the **Deck**.
  - Two tmux servers: a sessions server and an `swb`-owned UI server holding disposable Decks. (Amended by ticket 09: the sessions server embeds its config too.)
  - A Deck is a roster beside a Stage (a nested client driven by `switch-client`). The prefix is `M-a`.
  - Hover starts pi in the background after 500 ms, without ever blocking the TUI.
  - One editor per directory, swapped onto the Stage.
  - A consumed `SWB_MANAGED` token marks managed processes, and `$TMUX` is hidden from pi. pi mints ids.
  - Revive is gone. Archive refuses during a turn and kills pi, plus the editor if it was the directory's last open session.
  - No daemon. Every action is agent-drivable, and the Deck is capturable as text.

## Not yet specified

- **PR badge**: a 🚀-style glyph when the session's branch has an open PR on GitHub, Bitbucket (hosted), or GitLab. That means forge detection from the remote, auth per forge, and a caching and refresh cadence. Deferred to a later stage, but in scope.
- **pi-sessions `swb` launch backend**: managed sessions hide `$TMUX` from pi, so pi-sessions' directional handoffs are unavailable there. The fix is a pi-sessions backend that launches a handoff as a new managed session. Follow-up work in pi-sessions.

## Out of scope

- **libghostty-based terminal embedding**: the escape hatch if the tmux Deck proves inadequate. Avoid it if at all possible.
- **Claude Code support**: deferred. The schema should not preclude it, but no recorder is built here.
- **Cross-host rosters** (seeing pod042 sessions from a laptop): each host stands alone.
- **Herdr / agent-deck adoption**: not available, or not reliable, on the work Mac.
